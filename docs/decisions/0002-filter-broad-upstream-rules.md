# 0002 · 过滤上游中的过宽规则，提醒所有宽泛规则

- 状态：已采纳（2026-11-08，用户提出）
- 补充：[0001](0001-deviations-from-spec-1.5.md) #7「上游规则只保留匹配条件」

## 背景

上游规则剥掉策略字段后，只剩匹配条件。少数条件的范围大到失去分流意义：

- `DOMAIN-KEYWORD,ads` 会命中所有包含 `ads` 的域名，如 `uploads`、`downloads`。
- `IP-CIDR,0.0.0.0/0` 等于全部 IPv4。
- `AND,((NETWORK,UDP),(DST-PORT,443))` 等于全部 QUIC。

这些规则原本配合 `REJECT` 等策略使用。被放进用户的策略组后，会把大量无关流量带进去。

在真实 profile 中，`China` 合集出现了 `DOMAIN-KEYWORD,microsoft`，`AI` 合集出现了 `DOMAIN-KEYWORD,twitter`。品牌关键词同样会误伤，但通常是规则作者有意为之。

## 决定

1. 每条规则判为普通、宽泛或过宽三级，判定标准见 [broad-rules.md](../rules/broad-rules.md)。
2. **上游**的过宽规则在构建时过滤，不写入规则文件。
3. **手写**规则不过滤，按原样保留。过宽时给出警告 `W_BROAD_RULE`。
4. 宽泛与过宽规则都列入随规则文件发布的 `reports/broad-rules.md`。每次的更新说明列出本次过滤的条目，以及新出现的宽泛规则。
5. 通用词关键词表打包在 `src/domainrouter_v2/data/broad_keywords.txt`，内容来自公开数据（最常见的 DNS 标签、主流规则集），逐节注明依据。公共后缀判断使用打包的 Public Suffix List ICANN 段。

## 取舍

- **只过滤、不扩大**：过滤只会缩小来自上游的匹配集合，而且每一条都有记录。用户需要时，可以把规则手写回 my.wei。
- **品牌关键词只提醒**：`google`、`microsoft` 这类关键词的误伤真实存在。但删除它们会让规则作者明确想要的匹配失效，所以列入清单，由用户判断。
- **不在 YAML 中逐条标注**：Mihomo 逐行解析时会跳过整行注释，但行尾注释会经过 YAML 解析器。所以只在文件头注释中给出更新说明的链接，清单单独成文。
- **等价验证的范围**：语义层与内核层对照的是过滤之后、优化前后的结果。过滤是有意的改动，不在等价性证明之内。
